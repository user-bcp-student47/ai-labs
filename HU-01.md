# HU-01 — Bootstrap seguro de autenticación

## Origen
- **H-AUTH-08 — Credenciales de bootstrap fijas habilitadas en producción** (Pendiente). Evidencia: `auth/src/main/java/com/bcp/workshop/auth/UserRepository.java:27,38,51,143,149`; `auth/src/main/java/com/bcp/workshop/auth/AuthService.java:21`; `auth/src/main/resources/application.properties:3`.
- H-AUTH-02, relacionado con la firma de tokens, figura como Resuelto en `HALLAZGOS.md` y no se incluye como hallazgo pendiente de esta historia.

## Contexto
Durante la inicialización, el repositorio siembra una cuenta de rol elevado con credenciales fijas también en producción. La autenticación exitosa produce un token con el rol de la cuenta; por tanto, un bootstrap predecible puede permitir obtener una identidad autenticada con privilegios. Esta historia aborda únicamente el riesgo H-AUTH-08 registrado en la matriz; no presupone una política de aprovisionamiento todavía no acordada.

## Ajustes necesarios
- Definir una política segura para inicializar cuentas: impedir la siembra de credenciales fijas en producción o acordar un mecanismo de bootstrap controlado y externo a valores fijos en el código.
- Separar explícitamente el comportamiento de bootstrap por entorno, sin alterar la emisión de tokens firmados para autenticaciones válidas.
- Mantener las credenciales de prueba aisladas y no registrar credenciales, secretos ni tokens.
- Documentar la política escogida y sus requisitos operativos antes de implementarla.

## Criterios de aceptacion
- Con una base de datos nueva y perfil de producción, la inicialización no crea una cuenta accesible mediante credenciales de bootstrap fijas; comprobarlo con una prueba de integración sobre una base temporal.
- Una autenticación sin una cuenta inicializada o aprovisionada válidamente no obtiene un token; comprobarlo mediante `POST /auth/login` y verificar el estado y la ausencia del campo `token`.
- En el entorno de pruebas, el mecanismo de preparación de usuarios permite ejecutar las pruebas de login sin utilizar credenciales reales; comprobarlo con la suite de autenticación.
- El mecanismo y las condiciones de bootstrap seleccionados quedan descritos en configuración o documentación revisable; verificarlo mediante revisión del artefacto actualizado.
- Los logs generados durante inicialización y autenticación no contienen credenciales, secretos ni tokens; comprobarlo revisando la salida de una prueba de inicialización y login.

## Evidencia esperada
- Prueba automatizada que inicializa una base temporal con configuración de producción y verifica que no se habiliten cuentas con credenciales fijas.
- Pruebas del endpoint que confirman que una cuenta no aprovisionada no recibe token y que el flujo autorizado conserva la respuesta de login esperada.
- Salida de la suite de pruebas de autenticación y reporte de cobertura correspondiente.
- Configuración o documentación que registra la política de bootstrap acordada, sin valores de credenciales ni secretos.
- Revisión de logs de prueba que confirme la ausencia de credenciales, secretos y tokens.
